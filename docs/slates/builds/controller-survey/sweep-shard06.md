- **Defects**
  - TitleTransferController L156/189: the parcel goes to `receiver.getTemplatePath()`. Every player Avatar shares one lineage templatePath, and `AccessRegistry.subjectOwnsAsPlayer` matches on `getIdentityPath()`. So the title is written to a key no one owns, and every player collapses onto it. Should be `getIdentityPath()`, which the shares branch in the same file already uses (L219).
  - ShootController L148→153/178: `spendOne(ammo)` destructs the last round, then `Mml.thing(ammo)` and `ammo.getPresentation()` are read off the destroyed object (the scene and `spec.embeds`). Hit location is hard-coded `body.torso` (L172).
  - SteepController L81-93: if `steepsInto` resolves to no Material, the slot's payload is still wiped and the solute is still destroyed. That is a silent loss (refuse/skip/throw). It also never re-checks that the solute or vessel still exist after 60 s.
  - FightYieldController L338-343: narrates "You yield" before the act and ignores `yieldFight()`'s false result.
  - TitleSubdivideController L112-120: the zone template is minted before `ParcelApi.subdivide`, with no rollback if that fails.
- **Hard cases**
  - FightStatus L225: when `perceiveCombat` fails, it shows the opponent's TRUE poise band. Is that a display default (presentation) or a perception gate (rule)? Question: when a read fails, does the controller fall back to the truth, or to nothing?
  - Fit L93-97: one word can name a part keyword or a recipe. The priority order between them is routing that today's view grammar can't express. Does a rule decide it, or a missing binder feature?
  - Defend: three acts behind one word. The order "try intervene first" is the disambiguation. Is that a choice about asking (presentation) or a fact of the world (which act it was)?
  - Wash `findWater` calls `Shore.drawAt` at parse time, before the step is accepted. Whether a refused or busy wash has already drawn water depends on whether a draw depletes anything, which can't be settled without reading Shore.
- **Rules (new)**
  - (12) A controller that inherits from another controller to reuse anything other than words has found an object protocol. Bathe extends Wash for `findWater`/`findCleansers`; Stir extends Knead (words only: fine).
  - (13) A forecast is the object's. If the controller tells the player "this will take X" and computes X itself, the forecast and the clock can disagree (Dry `prospectFor` vs `Wet.dryingHours`).
  - (14) Duration and effort live in the plan, never as controller constants. Every plan-protocol controller in this shard (Cut, Dip, Knead, Shape, Paint, Impress) is clean. Every one still holding `*_MS` + `effortW` (Heat, Stir, Repair, Wash, Bathe, Steep) is 35-60% rule.
  - (15) The engine returns the condition, never the sentence, in BOTH directions. Splice and Store get `out.line` from the model, which leaves a replacement nothing to replace. Name it alongside rule 2 as its mirror failure.
