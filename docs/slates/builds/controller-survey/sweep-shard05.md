**Defects**
- `bulk/WaterController` L149-176: on full ponding ground, the whole can goes to the null sink before `takeStanding`. If that returns 0, the player is told "already wet through" and the water is already gone.
- `charactergen/TraitsController` L370-378: `Mml.unorderedList` gets bare bodies without `Mml.li`. That is the run-together blob ChronicleController's comment (L277-280) says it fixed. Traits was never fixed.
- `banking/TreasuryController` L108-122 and `HouseDrawController` L302: the refusal is picked by regex on the engine's message, and every other error is misreported ("has no account" / "do you have an account?").
- `banking/HouseDismissController` L214: a named org is resolved with `findByTemplatePath`, while Appoint stands it up with `StuffApi.singleton`. Dismissing from a non-resident org says "There is no organization at X".
- `banking/WalletController` L364-370: `freeze` with no active account freezes the card but issues none, yet says "a fresh card is issued".
- `charactergen/EmbodyController` L715-730: `user.playerIds.push` + `save` runs before the clone. A failed clone leaves an orphan id in the roster, even though the comment calls this "the atomicity boundary". `setSex` errors are swallowed silently (L736-739).
- `bulk/SipController` L291: no `fromSlot.settle()`, unlike Drink and Fill, so a sip reads unsettled state (likely; unverified at runtime).
- `banking/ReserveController` L275: `priceIndex()` takes no currency but is printed in every currency's block.

**Hard cases**
- *Passage:* the price is per-route on purpose, so temples can sell a better return. When the controller IS the only embodiment of a route, do the route's terms belong to a row or object the controller names? Otherwise a player who rewrites `passage`'s wording can also make coming back free.
- *Lock/Unlock:* is the order of refusals (visible state before secret key) a rule (`canLock`) or presentation? It decides what a stranger learns, so it is a rule. But rule 1 says only "condition", not "order".
- *Pour's `startsWith('reachable:')`:* the controller needs to know whether an arg was defaulted. Should the binder mark `defaulted: true` on the `MqlOneResult`?
- *Chronicle/Competence privacy:* hiding a player's record looks like a display choice, but it is the same predicate the subscription gate enforces. A duplicated permission is a rule even when its only effect is not showing something.
- *Embody FIELDS:* the field table is a projection for the client, which is presentation. Its `validate` and `apply` halves are rules. Should one table hold both?

**Rules (new)**
- R12 *A mutator that asks nobody must not be reachable from a controller without its gate:* when authority is a separate call the controller must remember, put it inside the mutation (`lock(actor)`). Evidence: Lock L113-130 ("`lock()` moves the bolt and asks nobody; this is the ask").
- R13 *A refusal the controller branches on is a return value, not an exception:* no `err.message` regex, no tag stripping. Evidence: HouseDraw L302, Treasury L109, BankingControllerBase `refusalWords` L48-52.
- R14 *A default that decides WHOSE book changes is not a choice about asking:* it has one home on the model. Evidence: three different "which house" derivations, `houseIRun` (authority), `resolveHouse` (employs/proprietor/wallet) and `useHouse` (`businessAt`); HouseControllerBase L45-46.
- R15 *A controller is a leaf:* nothing imports from it. Evidence: `validSexSet` is exported from EmbodyController (L499) and consumed by `Login`.
- R16 *Typed text reaches MQL only through the binder:* a controller never builds a query from a raw phrase. Evidence: RecordControllerBase L86 `MqlApi.resolveMany(asked, …)`.
