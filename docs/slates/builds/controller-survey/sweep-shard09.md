## After the table

**Defects**
- **SearchController:70.** `const onComplete = () => this.resolveAndRender(...)`. On the scheduled path the completion calls a method on the controller clone, which `CommandGiver._executeOne` destroys when `execute` returns. A destroyed Stuff answers every call with a no-op (`security.ts:1525`). So a timed `search` probably plays its begin line and never resolves, renders or records `searched`. `lint:completion-this` misses this because its regex only matches the inline `onComplete: () => {` form, not a hoisted `const`.
- **TeleportController:320-321.** Same defect, same lint blind spot: `const onComplete = () => { void this.resolveAnchoredCast(...) }`. An engaged anchored cast would never arrive.
- **TeleportController:92 + teleport.yaml scope `[reachable, here, peers]`.** Fork 1 (free movement in a held extent) only runs when `destination.stuff` binds, which only happens for something already in front of you. A distant place in your own extent falls through to `anchoredCast`, which needs the gift and mana: "free inside your extent" mostly doesn't happen. The unit tests set `model.destination` directly and skip the binder. Needs a drive to confirm.
- **UnhitchController:48 + unhitch.yaml `requires: [VisibleMixin, HaulableMixin]`.** `DraftAnimal` is `Mountable(Hauler(Beast))` and not Haulable, so the help's own example `unhitch horse` is refused at bind and the `isHauling(t)` branch is dead.
- **LocomotionControllerBase:313 `arriveAfter`.** A refusal at arrival sends a line but writes no note. It runs outside the command, so this is minor.

**Hard cases**
- **Assess and Map:** is "what this viewer may KNOW" (competence bands, staleness of a claim) a game rule or presentation? A rewrite that changes only wording must copy it, and a rewrite that drops it leaks diagnoses. Rule question: should a read verb get a *viewer-scoped structure* (Examination, MapView) from the model, so that what may be known lives there and the controller only words it?
- **Feel `temperatureCause`:** choosing which cause to name is half wording and half a claim about the world.
- **Listen:** naming sources by `getPresentation()` with no perception gate. Is it presentation, or a perception leak?
- **Survey:** a composite report over four objects. Is a "report verb" one head or several? Its branches share no refusal and no outcome, but no part of it costs anything.
- **Unhitch with no ownership check:** a missing permission is invisible to the replacement test, because a rewrite would copy the absence.

**Rules (new)**
- **(12)** A world fix copied into more than one controller's prelude means the object's entry point is missing. Evidence: `WaterSurface.giveWay(actor, true)` appears in LocomotionControllerBase:322, SwimController:40 and LieController:50, each preceded by the same `supports() && openWaterAreaM2()` test.
- **(13)** A completion closure must not capture `this` in any form. The lint should check what a completion closes over, not the shape of the `onComplete:` key. Evidence: Search:70 and Teleport:320 both escape the lint.
- **(14)** A view's `requires:` and the controller's branches must describe the same set of hosts. A branch the view cannot bind is dead code that the help text advertises. Evidence: unhitch.yaml / UnhitchController:48.
- **(15)** A read verb must not mutate state, even as a side effect of reading it. Evidence: Survey:245 calls `floor.reconcileStalls()`; Feel:126 inflicts a burn from a perception verb. If the burn is intended, `feel` is an act, not a read, and needs the act's plumbing on the object.
