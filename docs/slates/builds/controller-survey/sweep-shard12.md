**Defects**
- TuneControllerBase.ts:130-141: `serviceHandle` returns `{ok:false}` on a failed character resolve with no message and no note (the docstring says it notes). `tune off|who|history <unknown char>` and `tune <char> <msg>` do nothing at all.
- WatchController.ts:211→216-220 (and 178→187-190): when a shared screen refuses the source (`source-refused`, 266-271) the controller falls through and still follows the stream's chat, after reporting a refusal.
- ErrorsController.ts:93: the PM-only privacy gate on the console ring is only here. `DiagnosticApi.rawTail` (api/diagnostics.ts:147) is an open static, so any author code can read other players' command lines.
- ConfigController.ts:379: Tier C entrenchment is enforced only by this controller. `AppLogic.setSetting` (AppLogic.ts:87) writes any key.
- PressController.ts:168-183, 252-277: the operator's headline/body caps (`press.*MaxLength`) are read nowhere else. `PressApi.publish/edit` accept any length.
- WikiEditController.ts:221-224 vs 259-263, 277-279: frontmatter is saved before the body prompt. A cancelled editor reports "Edit cancelled" and a rev conflict reports "Nothing was overwritten", although title, tags and so on already changed.
- WikiRegistry `history`/`revisionAt`/`getBody` are ungated and return unredacted source. The criterion-67/68 redaction exists only in the History, Diff and Edit-conflict controllers.
- JobApplyController.ts:84-93: hiring criteria are a separate call from `Organization.appoint` (Organization.ts:545, `@Final` only, ungated). A rewrite that calls `appoint` skips them.
- PracticeController.ts:362: a non-advancing actor gets a silent no-op. job.yaml `post` help omits `watch`/`recover` and still says "guard my shop … refused", which the `watch` template contradicts.

**Hard cases**
- WikiControllerBase: the controller CLASS is the security principal (`FromModule … includeSubclasses`). Replacing a wiki controller means subclassing the base, so permission lives in a noun base (rule 11) on purpose. Question: may a call-security gate ever name a controller, or must it always name the actor?
- `watch horizon` vs `watch <stream>`: one word, two unrelated acts. Is "split" a controller issue or a view issue (two verbs sharing a word)?
- JobPost's condition phrase: is a per-template grammar parsing (view) or a game rule (what work is verifiable)? The view has no way to declare a sub-grammar for a greedy string.
- TestHarness `clockLine` (now/86400): is it presentation of the clock or a calendar fact recomputed? It drifts silently if the calendar's day changes.

**Rules (new)**
- (12) A gate that protects a third party (privacy, redaction, entrenchment tier, operator cap) sits on the read/write it protects, never in the verb. Test: name another caller (CMS, REST, author code); if it skips the gate, the gate is misplaced. Evidence: Errors:93, Config:379, Press:168, WikiHistory, WikiDiff:140.
- (13) A check and the act it licenses are one method on the object (`house.apply` → verdict or appointment), never "consider, then do" in the controller. Evidence: JobApply:84-93.
- (14) A security principal is the actor, never a controller class. Evidence: WikiControllerBase header 6-11.
- (15) A value type parsed in two or more controllers (durations, enum tokens, rev numbers, `kind:ref`) is a missing view/binder arg type (`duration`, `choices:`). Evidence: Press:399, StreamController, TestHarness:301; Press:345/355, Practice:344, Errors:149, WikiProtect. No view key for an enum exists today.
