The prompt is a lot of things

One slot, three occupants. At rest it renders prompt.format — a Liquid template the player owns. A foreground prompt takes the slot. Everything else waits above it.

Only one seizes input. foreground: false joins the stack without taking the slot — so a guild vote can arrive mid-forge and wait its turn rather than interrupting.

The queue strip shows what is owed. Picking one swaps it into the slot; the rest keep waiting.

Prose stays in the terminal. opts.body ships a world.prompt frame carrying the promptId, so long-form context scrolls with everything else and the two are visibly tied.

Failure is not dismissal. A validator returning a string emits prompt-validation-failed and the prompt stays alive. The UI must never clear the answer.

A prompt remembers who asked. Every prompt is pushed from inside a running command, so the verb, its description and how long it has waited are all knowable at push time — they just need to ride the envelope.

That is what makes an abandoned prompt judgeable: cancelling is not dismissing a dialog, it rejects the awaiting command with PromptCancelledError. The button should say which command dies.

Two cancels. The ✕ on a prompt is prompt-cancel, one prompt. prompt cancel on the strip is the verb — all of them.
