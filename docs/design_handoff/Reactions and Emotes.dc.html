Why it renders this way

A reaction is an ordinary emote carrying one extra scope, inReactionTo. There is no parallel dispatch and no second data model — so there is no reaction UI, only an emote UI that sometimes points at an earlier act.

The tally is not the threshold

The count always accrues. suppressFanOut governs only the prose line. So the chip exists from the first reaction and never disappears — what the threshold decides is whether the act also earns a sentence.

Which is right: “Maren nods slowly” is worth a line when three people are present. The forty-seventh thumb is not.

Defaulted from audience size rather than hand-set. A three-person forge and a two-hundred-person stream are the same mechanism with opposite right answers.

Retroactive mutation

A chip attaching to a frame forty lines up is invisible in a scrolling log. Re-surfacing the frame would fix that and destroy the log, so instead the chip updates in place and a coalesced delta line appears only for your own acts.

You care that people reacted to you. You do not need a line for every reaction to everyone.

Familiar-biased sampling

The sink carries a per-viewer sample weighted toward people you know, so a chip reads “Tomas, Bramble and 45 others” rather than a bare count. Better than the platforms manage, and already on the wire.

The picker is an emote picker

Emoji are an alias surface over canonical verbs, so every cell shows the verb it sends and the bar fills with the real command. This is the most-used interaction in the product; it is the last place the command line should go quiet.

Emotes with grammar — ;wave bob happily — cannot fit a grid, so the picker reads the emote's declared slots and offers them. Typed stuff slots resolve by MQL; free slots are dashed.
